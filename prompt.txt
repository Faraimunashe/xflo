GOAL
Users must capture accounting entries (including backdated entries for the past 2 years) and generate:
- Account statement (ledger) with running balance
- Trial balance
- Income statement (profit/loss)
- Balance sheet
- Cash flow (direct method)

CORE ACCOUNTING RULES
- Double-entry accounting enforced
- sum(debit) == sum(credit) required to post
- Only POSTED entries appear in reports
- Users can save DRAFT entries
- Posted entries are locked
- Corrections are done via REVERSAL entries
- Never store balances in the database
- All balances calculated from journal_lines
- Disable posting until entry is valid and balanced

ENUMS (app/Enums, PHP native enums)
Create enums with string values:
- AccountType: asset, liability, equity, revenue, expense
- NormalBalance: debit, credit
- CashflowType: operating, investing, financing
- JournalEntryStatus: draft, posted, reversed
- JournalSource: tuition, levy, expense, bank, opening_balance, adjustment

BUSINESS LOGIC (Action Classes)

SaveJournalEntryAction
- create/update journal_entries + journal_lines
- do NOT allow editing if entry is posted
- allow draft saves with partial lines
- strict validation only enforced during posting

PostJournalEntryAction
- only allow if status == draft
- validations:
  - minimum 2 lines
  - account_id required per line
  - debit XOR credit per line
  - total_debit == total_credit
- set status posted
- set posted_at now
- set posted_by auth()->id()

ReverseJournalEntryAction
- only allow reversing posted entries
- create new journal entry with source adjustment
- description: "Reversal of entry #{id}"
- swap debit/credit for each line
- auto-post reversal
- update original entry:
  - status = reversed
  - reversed_entry_id = reversal id
